# Data-provider setup

Official-source ingestion uses approved HTTPS hosts, bounded size/time, pinned public DNS addresses, no redirects and subprocess document parsing. Register source jurisdiction, canonical identity, language, legal status, dates, licence, amendment relationships and permitted purpose before relying on it. CLI example: `python -m airspace.cli ingest --source-id easa-ear-uas-2026 --output runtime/sources/public`. Check the actual catalogue identifier before execution. The upstream HTTP response and checksum determine success; a prepared adapter or HTTP202 challenge is not a successful fetch. The registered monitor dispatches approved structured EASA XML archives through their separate isolated parser. CLI output remains private unless separately curated into the public library; tenant jobs write to their tenant source store.

Registry status separates source downloads, adapter contract tests and live integration acceptance. Luxembourg DAC and Italy ENAC material is a starting point pending full national reconciliation. UK applicability stays separate. Other country packs are installable catalogue data, not a validated-country claim. Inspect sources/coverage.json and SOURCE_REGISTER.md.

EUR-Lex anti-automation responses must be recorded as failures; do not bypass protections. Operator-controlled manual import of lawfully obtained originals is supported by the ingestion function with explicit metadata. Original-language documents remain original; translations must be labelled English translations with separate provenance and review.

Telemetry: POST /api/v1/telemetry/import accepts the versioned contract, only for a pilot or fleet manager. Supply genuine aircraft/mission IDs in the same tenant, live/replay mode, explicit permitted-use attestation and source rights reference. The server records manual-import provenance. A monitoring procedure must be independently approved before its stale threshold is used. This does not establish a vendor feed as connected or operationally accepted.

U-space: there is no universal European API. The release records distinct permission instruments and provider prerequisites. Actual provider-specific network identification, geo-awareness, flight-authorisation and traffic-information adapters require documented interfaces, coverage, contracts, credentials and acceptance evidence. No real provider is connected. Weather, terrain, population, official aeronautical data and geozones require source-specific permitted-use review; do not treat public access as commercial redistribution rights.

EUROCONTROL EAD Basic is research-only under its stated terms and is explicitly excluded from operational acceptance. Research data cannot satisfy a scheduling operational-feed prerequisite. For every real feed record event time, receipt time, last successful check, coverage, freshness policy, schema/interface version and integration-test evidence. A failed or silent connector does not establish unchanged conditions.
