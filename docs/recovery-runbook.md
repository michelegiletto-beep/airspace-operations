# Backup and recovery runbook

Back up the database, complete `runtime/objects/`, permitted source originals, model/experiment lineage and private audit key. The database alone does not contain attachment bytes. Restrict backup access and encrypt off-host storage. Keep an external audit-head checkpoint and document recovery point and recovery time objectives for the deployment.

SQLite: stop writers for a coordinated object-store snapshot, then run `python -m airspace.cli backup --output private-backups/airspace.db`. The SQLite online-backup API preserves a consistent database snapshot. Copy immutable object blobs and the audit key separately. Run `python -m airspace.cli restore --input private-backups/airspace.db --target runtime-restored/airspace.db`; existing targets are refused. Supply the original audit key and verify every organisation with `airspace verify --organisation-id ID`. Check `PRAGMA integrity_check`, attachment hashes and record counts before directing users to the restored service. Never overwrite an active operational instance during a restore drill.

PostgreSQL: use supported `pg_dump --format=custom` with credentials provided through a protected service file or environment, never a command-line password. Restore with `pg_restore --exit-on-error --single-transaction` into a new database with required extensions and compatible roles. Restore object storage from the same checkpoint. Set AIRSPACE_DATABASE_URL to the new database, run migrations and audit verification, then execute tenant isolation, export and reservation acceptance tests. The initial environment lacked PostgreSQL/Docker; only a separately recorded actual drill establishes this path as verified.

Worker crash: leases expire and retry within the bounded budget. Inspect job attempts and state, reconcile any stale Running job, then resume only after input review. Paused/cancelled jobs cannot commit a late result. Database interruption must not produce a successful API mutation; transactional records, audit and outbox commit together. No data-recovery action issues aircraft commands.

Evidence integrity failure: restrict the affected object, retain corrupted bytes as investigation evidence, restore from a hash-verified copy and record the incident. Do not regenerate a missing authority receipt or replace an original silently. Record measured restoration duration and the verification command outputs in the deployment's private evidence archive.
