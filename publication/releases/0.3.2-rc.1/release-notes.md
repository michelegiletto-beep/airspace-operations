# Release 0.3.2-rc.1

Engineering candidate for self-hosted civilian UAS planning and decision support. The original specification remains incomplete. Stable release and operational acceptance remain false.

The dependency audit identified three upstream denial-of-service advisories affecting the previous `pypdf==6.21.3` pin: [GHSA-5849-834g-hvw5](https://github.com/py-pdf/pypdf/security/advisories/GHSA-5849-834g-hvw5), [GHSA-mfr5-77xh-9j7h](https://github.com/py-pdf/pypdf/security/advisories/GHSA-mfr5-77xh-9j7h) and [GHSA-cggf-277g-3q54](https://github.com/py-pdf/pypdf/security/advisories/GHSA-cggf-277g-3q54). This candidate pins `pypdf==6.21.4`, the fixed version identified by those audit records, in the project and hashed core/development locks. The initial failed audit is preserved under `release-evidence/v0.3.2-rc.1/attempts/pre-security-update/`; corrected source, dependency and installation gates are required for this release. PyPDF retains its BSD-3-Clause licence and attribution requirements.

Frozen 0.3.1 artifacts include the affected 6.21.3 pin and remain unchanged. Publishing a new candidate does not update an existing installation. An affected installation needs a reviewed fixed runtime before processing untrusted PDFs. No exploit, compromise, customer incident or flight event was demonstrated by this dependency review.

The Operations workspace explains who can prepare a mission proposal. Both mission-creation buttons use the native disabled state for roles other than planner or pilot. An accessible description identifies the required roles, and a separate control opens the existing authorisation-case workspace. This avoids presenting an unavailable action without an explanation. Existing server permissions remain authoritative; the interface grants no role or permission. A role that permits proposal creation does not establish an authority-issued operating basis, internal dispatch readiness or flight execution.

Publication checks inspect encoded raster containers and their filename extensions. The selected screenshot and all supported raster files in the current candidate's media namespace are checked, including unselected mobile captures. Bounded file sizes, entry counts and directory depth prevent unrestricted media scanning. New JPEG captures use `.jpg` in the `0.3.2-rc.1` namespace. The frozen 0.3.1 mobile capture keeps its original JPEG bytes and incorrect `.png` filename; previous tags, archives and evidence are preserved. Container checks do not establish visual correctness, provenance or rights, which require separate review.

The owned animated companion, animated fallback, saved pause and reduced-motion preferences retain their existing boundaries. Conversations and personal tasks remain private to their author. Internal draft actions still require explicit confirmation, current actor permissions and input versions. No aircraft commands, external correspondence, authority decisions, external submissions or self-approval are added.

No new local-model generation, student training, operational prediction or model-performance improvement is claimed. Existing experimental weights and datasets are unchanged. A pristine operational workspace remains empty. Schema marker 3 is unchanged; follow the existing upgrade, backup and restoration instructions. Qualified national review, lawful operational data, approved procedures and operator acceptance remain required.
